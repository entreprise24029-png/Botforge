# ChannelForge | مطوّر القنوات

منصة Telegram تتيح لعملائك إنشاء بوتات قابلة للتخصيص وتطوير قنواتهم ونشر المحتوى فيها مقابل اشتراك مدفوع.

## هيكل المشروع

```
support_bot_factory/
├── main.py                       # البوت الرئيسي (نقطة التشغيل)
├── requirements.txt
├── .env.example
├── core/
│   └── bot_manager.py             # يشغّل/يوقف بوتات الدعم الفرعية
├── bots/
│   └── support_bot_template.py    # القالب الذي يعمل به كل بوت دعم فرعي
└── database/
    ├── models.py                  # جداول قاعدة البيانات
    └── db.py                      # دوال التعامل مع القاعدة
```

## التشغيل

```bash
pip install -r requirements.txt
cp .env.example .env
# عدّل .env وضع فيه توكن بوتك الرئيسي وآيدي حسابك
export PORT=8000
export BOT_TRANSPORT=webhook

uvicorn app:app --host 0.0.0.0 --port $PORT
```

## تدفق الاستخدام

1. العميل يبدأ محادثة مع بوتك الرئيسي ويرسل `/start`
2. يضغط «صنع بوت جديد» أو يرسل `/create_bot` ثم يعطيك توكن بوت أنشأه عبر @BotFather
3. النظام يتحقق من التوكن ويسجّله في قاعدة البيانات (غير مفعّل بعد)
4. يختار Stripe أو BaridiMob بالدينار أو RedotPay
5. بعد نجاح Stripe/RedotPay، أو موافقة الأدمن على إثبات BaridiMob، يُفعّل الاشتراك
6. بوت العميل يبدأ العمل تلقائيًا فورًا

## الميزات المضافة الآن

### 🔐 تشفير التوكنات
- `core/security.py` يشفّر توكن كل بوت عميل بـ Fernet قبل تخزينه في القاعدة.
- ولّد مفتاحك الخاص واحفظه في `.env` تحت `ENCRYPTION_KEY`:
  ```bash
  python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
  ```
- **لا تفقد هذا المفتاح ولا ترفعه لـ Git** — بدونه لا يمكن فك تشفير أي توكن مخزّن سابقًا.

### 💳 بوابة الدفع (Stripe)
- عند `/create_bot` يحصل العميل تلقائيًا على رابط دفع Stripe Checkout.
- بعد نجاح الدفع، Stripe يستدعي `/stripe/webhook` في لوحة التحكم فيفعّل الاشتراك تلقائيًا.
- عملية `main.py` تكتشف التفعيل خلال دقيقة (عبر `sync_newly_activated_bots`) وتشغّل بوت العميل فورًا — بدون أي تدخل يدوي.
- خطوات الإعداد على Stripe:
  1. أنشئ حساب على https://dashboard.stripe.com
  2. أنشئ Product + Price (شهري) وخذ `price_id` → `STRIPE_PRICE_ID`
  3. خذ `STRIPE_SECRET_KEY` من صفحة API Keys
  4. أنشئ Webhook يشير إلى `https://your-domain.com/stripe/webhook` مع الحدث `checkout.session.completed`، وخذ `STRIPE_WEBHOOK_SECRET`
- إذا فشل الدفع التلقائي (مثلاً المفتاح غير مضبوط)، يبقى أمر `/activate <bot_id> <days>` كخيار احتياطي يدوي من داخل تليجرام، بالإضافة لزر "تفعيل يدوي" في لوحة التحكم.

### 🇩🇿 الدفع عبر BaridiMob بالدينار الجزائري
- يختار العميل BaridiMob بعد تسجيل البوت، وتظهر له قيمة `SUBSCRIPTION_PRICE_DZD` وبيانات التحويل الموجودة في `.env`.
- يرسل العميل صورة الإيصال أو ملفه داخل البوت الرئيسي.
- يُرسل الإثبات للأدمن مع زري **موافقة/رفض**. عند الموافقة يُفعّل البوت 30 يومًا تلقائيًا.
- هذا المسار **مراجعة يدوية للإيصال**؛ لم تتم إضافة تحقق آلي مزعوم لأن ذلك يتطلب بوابة تاجر أو API رسمية من بريد الجزائر/مزود دفع معتمد.
- ضع `BARIDIMOB_RIP` وبيانات الحساب في Secrets/متغيرات البيئة، ولا تضع أرقامًا حقيقية داخل Git.

### 🖥️ لوحة التحكم الويب
- `dashboard/app.py` (FastAPI) تعرض: عدد العملاء، عدد البوتات، القنوات/المجموعات، عمليات النشر الناجحة والفاشلة، وجدولًا تفصيليًا بكل بوت وحالته.
- محمية بـ Basic Auth بسيط (`DASHBOARD_USER` / `DASHBOARD_PASSWORD` في `.env`) — لإنتاج حقيقي استبدله بنظام جلسات/JWT حقيقي.
- التشغيل الموحّد للوحة والبوتات والـ Webhooks في عملية واحدة:
  ```bash
   uvicorn app:app --host 0.0.0.0 --port $PORT
  ```

### 🪙 RedotPay Connect (دفع بعملات مستقرة/كريبتو)
- `core/redotpay_signature.py` يولّد ويتحقق من توقيعات **SHA256withRSA** (نظام مختلف تمامًا عن Stripe الذي يستخدم سرًا بسيطًا).
- `core/payments_redotpay.py` ينشئ طلب دفع (Paylink flow) ويرجع رابطًا جاهزًا للعميل.
- العميل الآن يختار بين "بطاقة بنكية (Stripe)" أو "عملات مستقرة (RedotPay)" بزر مباشر بعد تسجيل بوته.
- خطوات الإعداد على RedotPay:
  1. سجّل كتاجر على https://www.redotpay.com/redotpay-connect وأكمل التحقق (KYC)
  2. اطلب من مدير حسابك تفعيل صلاحية المطورين (Developer Access)
  3. ولّد زوج مفاتيح RSA خاص بك:
     ```bash
     openssl genrsa -out redotpay_private_key.pem 2048
     openssl rsa -in redotpay_private_key.pem -pubout -out redotpay_public_key.pem
     ```
  4. ارفع `redotpay_public_key.pem` في لوحة تاجر RedotPay، واحفظ الملف الخاص بأمان على سيرفرك فقط
  5. انسخ مفاتيح RedotPay العامة الرسمية (Sandbox/Production) من [توثيقهم](https://redotpay.readme.io/docs/redotpay-api-request-signature-and-verification-guide) إلى `.env`
  6. اضبط رابط الويبهوك في لوحتهم إلى: `https://your-domain.com/redotpay/webhook`
- ⚠️ **مهم**: هيكل استجابة `create_payment_order` والحقول الدقيقة في الويبهوك (`status`, `outerOrderSn`...) قد تختلف قليلًا حسب نسخة حسابك — تحقق منها بأول طلب فعلي في بيئة Sandbox قبل الانتقال للإنتاج، وعدّل القراءة في `core/payments_redotpay.py` و`dashboard/app.py` إذا لزم.

### 🆕 إدارة القنوات والمنشورات من داخل بوت العميل
- بعد تفعيل بوت العميل، يظهر للمالك زر **ChannelForge** مع أزرار إدارة القنوات، إضافة منشور، حذف منشور، الإحصائيات واللغة.
- لإضافة قناة: اضغط **إضافة قناة** ثم أعد توجيه أي منشور من القناة. يمكن أيضًا إرسال `@username` أو ID القناة، أو إرسال صورة للقناة مع `@username` في التعليق. لا يمكن استخراج معرّف قناة من لقطة شاشة وحدها؛ لذلك يطلب البوت المعرّف بعدها.
- لكل دفعة نشر رقم منشور مستقل. يعرض البوت نتيجة كل قناة، ويحفظ النجاح والفشل، ويمكن حذف الرقم لاحقًا من كل القنوات التي نجح النشر فيها.
- اللغات المتاحة حاليًا: العربية، الإنجليزية، الفرنسية، التركية والإسبانية. يمكن إضافة لغات جديدة إلى قاموس `TEXT` في قالب البوت.
- لإسناد مجموعة دعم بشرية استخدم: `/set_support_group <bot_id> <group_id>` من البوت الرئيسي.

## نقاط ما زالت تحتاج استكمالًا قبل الإطلاق الفعلي

- **ربط ردود فريق الدعم بالمستخدم الصحيح**: يُحفظ ربط `message_id` في جروب الدعم بالتذكرة والمستخدم النهائي في جدول `ticket_messages`.
- **الوسائط والمرفقات**: يدعم بوت الدعم استقبال الصور والفيديوهات والملفات وإرسالها إلى جروب الدعم، كما يدعم رد فريق الدعم عليها وإعادتها للمستخدم النهائي.
- **قالب بوت قابل للتخصيص**: يتيح لمالك البوت تعريف أوامر وأزرار وردود تلقائية، تغيير اللغة، وتغيير رسالة الترحيب.
- **النشر في القنوات**: أضف القنوات من لوحة إدارة البوت أو عبر `/add_channel`، ثم أرسل `/publish` داخل البوت الفرعي لنشر نص أو صورة أو فيديو أو ملف في كل القنوات مع رقم منشور ونتيجة لكل وجهة.
- **Bot Maker على طريقة الرحلة المرفقة**: `/start` في البوت الرئيسي يعرض أزرار الصنع والبوتات والمساعدة، و`/my_bots` يعرض البوتات مع تأكيد قبل حذف إعداداتها من المصنع. الحذف لا يحذف حساب البوت من BotFather.

### 🧩 إعداد البوت القابل للتخصيص
نفّذ الأوامر التالية من البوت الرئيسي بحساب مالك البوت أو `ADMIN_ID`، واستبدل `BOT_ID` برقم البوت:

```text
/set_welcome BOT_ID رسالة الترحيب الجديدة
/add_command BOT_ID faq | إجابة الأمر
/add_button BOT_ID الأسعار | تفاصيل الأسعار
/add_auto_reply BOT_ID كلمة مفتاحية | الرد التلقائي
/add_channel BOT_ID -1001234567890 اسم القناة
/channels BOT_ID
/remove_channel BOT_ID -1001234567890
```

- اكتب الأمر المخصص في البوت الفرعي مثل `/faq`.
- تظهر الأزرار المخصصة تلقائيًا مع `/start`.
- الرد التلقائي يعمل عند احتواء رسالة المستخدم على الكلمة المفتاحية.
- بعد إضافة القنوات، أرسل `/publish` داخل البوت الفرعي، ثم أرسل المنشور كنص أو صورة أو فيديو أو ملف. يجب أن يكون البوت مشرفًا في كل قناة.
- **التجديد التلقائي وإلغاء الاشتراك**: يعالج Stripe الحدثين `invoice.paid` و`customer.subscription.deleted`.
- **مصادقة لوحة التحكم**: تستخدم جلسات موقعة وكلمات مرور مجزأة بـ bcrypt بدل Basic Auth.
- **تشغيل موحّد**: استخدم `BOT_TRANSPORT=webhook` و`PUBLIC_BASE_URL`، ثم شغّل `uvicorn app:app --host 0.0.0.0 --port $PORT`. نفس العملية تخدم لوحة التحكم وWebhook البوت الرئيسي وكل البوتات الفرعية.
- **النسخ الاحتياطي**: شغّل `scripts/backup.py` دوريًا عبر cron لحفظ قاعدة البيانات ومفتاح التشفير في مسارين منفصلين.

### 💾 النسخ الاحتياطي
- السكربت `scripts/backup.py` ينسخ SQLite باستخدام `backup API`، ويدعم PostgreSQL عبر `pg_dump`.
- تُحفظ قاعدة البيانات ومفتاح `ENCRYPTION_KEY` في مسارين منفصلين، ويُكتب ملف المفتاح بصلاحيات `0600`.
- اضبط `DATABASE_BACKUP_DIR` و`ENCRYPTION_KEY_BACKUP_DIR` على تخزين منفصل وآمن، ثم شغّل السكربت يوميًا عبر cron:
  ```cron
  0 3 * * * cd /path/to/support_bot_factory && /usr/bin/python3 scripts/backup.py >> /var/log/support-bot-backup.log 2>&1
  ```
- لا تضع ملف النسخة الاحتياطية أو المفتاح داخل Git، واضبط `BACKUP_RETENTION_DAYS` لتدوير النسخ القديمة.

## قاعدة البيانات

- `clients`: بيانات العملاء الذين اشتروا الخدمة
- `support_bots`: بوتات الدعم المُنشأة، توكناتها، حالة اشتراكها
- `tickets`: تذاكر الدعم التي يفتحها المستخدمون النهائيون داخل كل بوت فرعي
